Which sites change a GAM, and why? A coral trout example

The question

When a model is fitted to data collected at sites, a natural check is to leave each site out in turn and see how much the fit changes. For a GAM fitted with mgcv, leaving a site out changes two things. The coefficients move, and the smoothing parameters, which REML estimated from all the data, move too. A classical deletion diagnostic such as Cook’s distance holds the smoothing parameters fixed, so it only sees the first change.

gam_influence() refits the model twice for every site and compares the two refits:

  • fixed: the site is removed and the estimated smoothing parameters (and a negative binomial θ) are held at their full-data values. This is what a classical diagnostic sees.
  • added: what re-estimating them adds on top.
  • total: the change when everything is re-estimated.

Each is a weighted RMS change in the other sites’ fitted values, on the link scale. On a log link, an RMS of 0.02 is roughly a 2% change in their predicted means, as long as the individual changes are small.

This vignette runs it on a real model: coral trout on inshore reefs of the Great Barrier Reef.

The data

coral_trout holds 467 surveys of coral trout (Plectropomus leopardus) at 71 inshore reef sites in the Palm and Whitsunday island groups, from 2007 to 2018. Each site is fished or inside a no-take reserve (zoned in 1987 or 2004).

The model

This is Model A of the coral trout study (Song 2026): a negative binomial GAM with a random intercept for each site, a separate smooth year trend for each region, and smooth terms for habitat and environment.

m <- gam(count ~ REGION * NTR + EXPOSURE + depth +
           s(YEAR, by = REGION, k = 5) +
           s(rugosity, k = 5) + s(LHC, k = 5) + s(kd490, k = 5) +
           s(maxDHW, k = 5) + s(Cyclone, k = 5) + s(SITE, bs = "re"),
         family = nb(), data = coral_trout, method = "REML")

Running gam_influence()

One call does the whole analysis. Every site is deleted in turn, and each deletion needs one held refit and one re-estimated refit, so for 71 sites this takes about three minutes:

infl <- gam_influence(m, cluster = "SITE")

To keep this vignette quick, it loads the saved result of exactly that call. The script that made it is data-raw/coral_trout_influence.R in the package source.

infl <- readRDS(system.file("extdata", "coral_trout_influence.rds",
                            package = "gamfluence"))

A run on two sites takes a few seconds and shows the same numbers:

The plot

plot() puts each site at its fixed change (across) and its added change (up), on the same scale. Sites above the dashed line change the fit more through the smoothing parameters re-tuning than through the held-parameter refit.

plot(infl, n = 8)

Most sites sit in a cloud near the diagonal. 7 sites sit far above it, at the top left. Held at their full-data smoothing parameters, their deletion looks ordinary: their fixed changes run from 0.01 to 0.028, inside the range of the other sites (0.006 to 0.039). A classical diagnostic would not flag them. Once the smoothing parameters are re-estimated, each of them adds a change of about 0.062 to 0.065, between 2.2 and 6.4 times its fixed change.

The smoothing parameter of the Palm year trend jumps from 0.082 to 6,247. A smoothing parameter that large turns a smooth into a straight line: without OE4, the Palm year trend is no longer curved. The same happens for all 7 sites (HW2, L1, OE1, OE3, OE4, OS5, PS4), and straightening the trend moves the fitted values of every Palm site.

Why can one site do that? Fixing the Palm smoothing parameter at a range of values, re-estimating everything else each time, and comparing REML scores shows how flat the score is for that trend:

grid <- c(0.01, 0.1, 1, 10, 1e3, 1e5)
reml <- sapply(grid, function(l) {
  sp <- rep(-1, length(m$sp))
  sp[1] <- l                                  # s(YEAR):REGIONPalm
  as.numeric(gam(formula(m), family = nb(), data = coral_trout,
                 method = "REML", sp = sp)$gcv.ubre)
})
data.frame(lambda = grid, REML_minus_best = round(reml - min(reml), 3))
#>   lambda REML_minus_best
#> 1  1e-02           1.232
#> 2  1e-01           0.000
#> 3  1e+00           0.497
#> 4  1e+01           0.250
#> 5  1e+03           0.087
#> 6  1e+05           0.085

The curved trend (smoothing parameter near 0.1) is the best fit, but a straight trend (very large values) is worse by only 0.085 REML units, with a worse region in between. With two optima that close, removing one site can make the straight line win. For the coral trout study this says the shape of the Palm year trend is only weakly supported by the data, and any conclusion that leans on its curve should be read with that in mind.

Two optima

Because the REML score here has two optima, a single search for the re-estimated fit can stop at the worse one. gam_influence() therefore searches twice, from mgcv’s default starting values and from the full-data values, and keeps the fit with the better REML score. When the two searches end at clearly different fits, the site’s status says so and note gives the other fit:

table(s$status)
#> 
#>         ok two optima 
#>         53         18
x <- s[s$id %in% c("OE4", "W2"), ]
writeLines(paste0(x$id, ": ", x$note))
#> OE4: two REML optima: the better one is used (REML score lower by 0.47); the other gives total 0.0375
#> W2: two REML optima: the better one is used (REML score lower by 0.098); the other gives total 0.0751

For OE4 the straight trend is the better fit after deletion. For W2 the search from mgcv’s defaults stops on the straight-line plateau, but the curved trend is better, so the curved fit is used. A small REML difference means the data barely prefer one fit over the other, so treat those sites’ added and total with care.

Other groupings

cluster can be any grouping of rows, not only sites. For example, deleting whole surveys (each region in each year):

by_survey <- gam_influence(m, cluster = paste(coral_trout$REGION, coral_trout$YEAR))
plot(by_survey)

How it works

  • One representation for every refit. All refits reuse the full fit’s model matrix, identifiability constraints and penalties. So the changes measure the effect of deleting the site, not of rebuilding the basis from less data.
  • Two refits per site. The held refit keeps every estimated smoothing parameter (and θ) at its full-data value. The re-estimated refit estimates them again by REML, searched from two starting points.
  • fixed + added = total holds exactly for every fitted value. The table reports RMS summaries, and those do not add: total is never larger than fixed + added.
  • A scope guard stops with an error on models outside what the package supports, and a self-check confirms that the refits reproduce the original fit before any site is deleted.

How it is checked

The package’s tests check that the refits reproduce the original fit; that the held refit matches a closed form and Cook’s distance for a linear model; that re-estimated refits match ordinary gam() refits and are optimal under an independently coded REML criterion; and that row alignment, rank deficiency, two optima and out-of-scope models are handled.

A known-truth simulation (validation/planted_site.R in the source) planted one site with an extreme random effect in each of 20 datasets. Its fixed change never exceeded the null 99% line (0 of 20 datasets), while its added change exceeded it in all 20. Its influence ran through the re-estimated smoothing parameters, which a held-parameter diagnostic cannot see.

Scope and limits

gam_influence() supports gam(..., method = "REML") with gaussian, poisson, binomial and negative binomial families, one-dimensional thin plate smooths, s(g, bs = "re") random effects and by = factor; the README lists what is rejected. There is no null reference or p-value, so compare sites with each other rather than with a fixed cut-off.
